Top 20 Claude skills for software engineering

A weekly curated list. Software engineering only, no fluff.
Last updated Nov 7, 2026 (v2, no swaps). Next curation Saturday Nov 14, around 9am PT.
Rule: always 20. One in, one out. Dropped skills move to archive, never deleted.

How to use this list

  • Start with one workflow framework from 1-6, not all six.
  • Add the official Anthropic skills you actually need from 7-12.
  • Add one skill per real pain point after that: UI, understanding code, context, tokens.
  • Install only what you will use. Every enabled skill costs context.

Install: /plugin marketplace add anthropics/skills, or copy a skill folder into ~/.claude/skills/. Check the source repo first, commands change. This is an index, not a copy. Each entry links to its source. Star counts are from Oct 27-31 and move daily. Treat them as a popularity signal, not proof of quality.

Workflow and methodology

1Superpowers (about 306k stars)

Plan first, test-driven development, systematic debugging, subagent-driven work, verify before finishing.

Use when: you want Claude Code to act like a disciplined senior engineer instead of jumping straight to code.

2Matt Pocock Skills

Small composable skills for real engineering work.

Use when: you want bite-size skills you can adopt one at a time.

3Addy Osmani Agent Skills (about 101k stars)

Production-grade spec, build, test, ship workflows.

Use when: you want a shipping workflow, not just a coding helper.

4gstack (about 138k stars)

Team-in-a-box process: slash-command roles for design, eng management, review, QA, security, and release.

Use when: you want a full engineering-team process around your agent, not just a coding helper.

5BMAD-METHOD

Agile AI-driven development method.

Use when: you want an agile, role-based method for bigger builds.

6Planning with Files

Breaks tasks into steps and tracks progress in files.

Official Anthropic, software engineering only

From anthropics/skills (about 184k stars, 19 skill folders). Only the engineering ones made the list. Document, brand, art, and comms skills are in archive.

Use when: you build with the Claude API and want current facts, not the model's memory.

12webapp-testing

Test local web apps with Playwright for UI checks and debugging.

Frontend and UI

13UI-UX Pro Max

Design intelligence: styles, palettes, UX rules.

Use when: your UI looks AI-made and you want a real design system.

14Impeccable (about 98k stars)

Design vocabulary for agents: polish, critique, audit commands plus 62 deterministic anti-slop detector rules.

Use when: your agent-built UI looks generic and you want concrete, checkable design feedback.

Honest caveat: independent blind tests in Oct 2026 ranked UI-UX Pro Max first on one test, and a Subframe test the same month found impeccable the only one of four design skills that changed the look. Impeccable uses deterministic detectors instead of LLM judgment. Some design skills burn a lot of tokens. Use one design skill at a time and judge on your own brief.

Understanding, docs, context

15Understand-Anything (about 91k stars)

Turns a codebase into an interactive knowledge graph you can explore and ask about.

Use when: you are onboarding to an unfamiliar codebase.

16Context7

Keeps current library docs in front of the model.

Use when: Claude keeps using outdated library APIs.

17Claude-Mem

Persistent memory across sessions.

Use when: Claude forgets your project between sessions. Note: browser installs Oct 25-Nov 2 uploaded 30 days of prompts without asking; fixed in v15.8.3 (Nov 2) with a consent panel. Check the consent screen on install.

18Diagram Design (about 53k stars)

Architecture, flow, org, and timeline diagrams, 44 types, exports to HTML, SVG, PNG.

Use when: you need clean architecture diagrams from a codebase or a brief.

Efficiency and harness

19Caveman

Cuts output tokens hard while keeping technical accuracy.

Use when: you are hitting usage limits and want shorter output.

20ECC

Agent harness tuning: skills, memory, security, research-first workflow.

Use when: you want one harness setup across Claude Code, Codex, Cursor, and similar tools.

Both names have many mirrors. Use the linked repos. Do not install a fork without reading it.
